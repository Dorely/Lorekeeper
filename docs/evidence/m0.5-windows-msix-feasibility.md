# M0.5 local Windows MSIX feasibility evidence

Status: **Blocked after deterministic local package preflight**

Date: 2026-09-16

This evidence records only the local full-trust MSIX package preflight. It is not
evidence of Store acceptance, AppContainer confinement, an installed application,
OAuth, a provider call, import/export, printing, updater behavior, process tree,
or packaged data/history paths.

## Scope and result

The current local Windows environment built the Store-channel `win-unpacked`
closure from the Release package path, then ran the historical
`Build-M0MsixFeasibility.ps1`. That tool is superseded by
[`Build-WindowsMsix.ps1`](../../tools/msix/Build-WindowsMsix.ps1);
[the current MSIX runbook](../../tools/msix/README.md) records the production and
local-validation modes and the later 2026-10-05 package evidence. The historical
command below is retained as evidence, not a current invocation.
The package uses the local test identity in
[`Package.appxmanifest.xml`](../../tools/msix/Package.appxmanifest.xml), declares
`Windows.Desktop`, `runFullTrust`, `packagedClassicApp`, and `mediumIL`, and does
not claim AppContainer confinement.

| Check | Result |

| Store build metadata in contained `Lorekeeper.dll` | Exactly one `Store` value |
| MakeAppx SDK | 10.0.26100.0 |
| Package version | 0.3.17.0 |

| Signature | Passed embedded-CMS cryptographic integrity and exact ephemeral current-user signer validation |
| Package installation | Not performed |

The signed package SHA-256 was
`7ffbe77f4b05070aa8ad293a11240a6adf621fab1ee491b2487203c53e567ba2`.
Its generated report and every staged package artifact remain only beneath ignored
`.artifacts/m0.5-msix/`. The script removed the exact ephemeral current-user
certificate before exit; it did not add a trusted-root certificate or sign a
production package.

The CMS check is deliberately cryptographic/signature-identity evidence, not a
Windows trust-chain assertion. A self-signed local feasibility certificate is not
a production trusted publisher. Trusted installation, package registration, and
actual Store policy require the separately authorized test-profile session.

## Commands used

```powershell
.\scripts\build-windows-release.ps1 -KeepUnpacked -DistributionChannel Store
.\tools\msix\Build-M0MsixFeasibility.ps1
```

The release build was local, unsigned, and unpublished. The package command did
not call `Add-AppxPackage`, `Remove-AppxPackage`, a Store service, GitHub, an
updater, or a provider.

## Remaining authorization and evidence

M0.5 remains blocked until the owner separately authorizes a reversible,
disposable Windows test-profile session. That session must install one exact
generated package, collect sanitized package/process/data-path evidence, exercise
real import/export and application print preview followed by cancellation of the
native printer handoff, verify Store updater suppression, then uninstall that
exact package and remove only its generated certificate and ignored artifacts.

OAuth needs a separate safe test account and explicit authorization. Until then,
it is unperformed, not simulated. No Store submission, production signing,
publisher identity, external integration, or deployment is authorized by this
preflight.
