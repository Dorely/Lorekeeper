# M0.3 local performance baseline

Status: **Blocked — no timing baseline has been recorded.**

This report owns the local M0.3 measurement protocol and the first launch
attempt. It is intentionally not evidence for macOS, Store, packaging/updater,
provider, source-library, history, or shared-page performance.

## Reference environment

- Windows 10 Pro 10.0.19045, build 19045
- AMD Ryzen 7 9700X, 16 logical processors
- 31.6 GiB physical memory
- Unsigned local Release Electron package, version 0.3.17

This is a comparison environment, not a v1 minimum hardware requirement.

## Implemented local protocol

[`tools/performance/`](../../tools/performance/) generates deterministic,
sanitized v30 JSON fixtures with seed `Lorekeeper-M0.3-v1`:

- 25 chapters / 250,000 fixture words;
- one 10,000-block document containing exactly 1,048,576 UTF-8 text bytes;
- an explicit-only 50-source × 64 MiB (3.125 GiB) ASCII library descriptor.

The generated fixture manifest fixes file names, byte lengths, counts, and
SHA-256 hashes. The generator writes fixture data only below ignored
`.artifacts/performance/`, and production import UI—not SQLite writes—is the
only supported way to load the two project fixtures.

The opt-in trace accepts an output only below `.artifacts/performance/`. Its
newline-delimited records contain UTC timestamp, fixed metric, numeric duration,
and sequence only. It never contains manuscript text, document identifiers,
credentials, or request/provider data. The runner starts the packaged app with
isolated database, history, and Electron user-data directories; sets the
Development environment to prevent desktop update checks; hashes all package
files; and samples the Release process tree’s working/private memory every
250 ms. It retains raw ignored artifacts and calculates nearest-rank p95 after
five warm-ups plus 30 samples for input-to-visible-frame, save acknowledgment,
Undo, Redo, and editor-ready-after-navigation.

## First launch attempt — 2026-09-16

The local Release package started and completed startup with isolated data paths.
Its raw trace was empty because the available computer-control surface exposed
only an in-app browser and no native-app target for the Electron window. No UI
input was simulated, no browser substitute was used, and no timing result is
claimed. The app was terminated after the attempted session.

The ignored session retained its exact package-input hashes, host configuration,
and 250 ms process-memory samples for diagnosis only. It is not committed and
does not substitute for the required timing sample set.

## Required completion evidence

Use an explicitly authorized local native-Electron input surface or a local
operator to load the fixtures through the production import UI. Perform five
warm-ups followed by exactly 30 measured samples per metric, close the app to
flush the trace, and record the resulting p95 values, peak/process-tree memory,
package inputs, and any environmental background activity here. Explicitly keep
the few-GB library, streaming import/export, history, and M2 shared-page
workloads marked unsupported until their owning milestones measure them.
