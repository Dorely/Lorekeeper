# Security reporting

Please do not publish exploitable vulnerabilities, credentials, manuscripts, or
private data in an issue or pull request. Use GitHub's private vulnerability
reporting form when it is available:
[Report a vulnerability](https://github.com/Dorely/Lorekeeper/security/advisories/new).

If that form is unavailable, open a minimal issue asking the maintainer to
arrange a private reporting channel. Include no vulnerability details or
attachments until that channel is established. No public email address or
response-time commitment is currently maintained.

Include the affected version and platform, a synthetic reproduction, the
security impact, and any proposed mitigation. Never send a working project
database, API key, authorization code, or OAuth token.

Fixes target the latest stable release and current `main`; older releases do
not have a separate maintenance commitment. See [PRIVACY.md](PRIVACY.md) for
local storage and intentional network boundaries and
[SUPPORT.md](SUPPORT.md) for ordinary bug reports.
